# 场景：Hyderabad B300 持续申请

**目标：** 一个客户独立控制平面，固定 `ap-south-2` / `p6-b300.48xlarge`，一笔 Fleet 在批准的标准 AZ 里持续请求目标台数。默认 1 台 = 8 GPU，但不承诺库存、驱动就绪或训练恢复。

## 1. 先确认能走这个场景

完成 [公共准备](start-here.md)。管理员确认 HYD 已启用、P 类 Spot quota 足够、B300 兼容 AMI/驱动/CUDA 可用。无法启用 HYD 或没有配额时停在只读检查，不换成 CPU 或其他区域冒充 B300。

B300 客户部署与实机获配尚未验证。CPU 测试不能证明 B300 的实际启动 IAM 合格；出现权限拒绝时停下来审核，不复制本机测试角色的临时放宽条件。

## 2. 复制配置，统一身份

```sh
mkdir -p privateinputs
cp config/hyd-b300.example.yaml privateinputs/customer-a.yaml
```

填写这三处一致的身份：

| 位置 | 本指南采用的值 |
|---|---|
| CDK customer_id / YAML ownership_tags.customer-id | customer-a |
| CDK target_id / YAML target_id | customer-a-hyd-b300 |
| LT instance/volume 的 capacity-target-id | customer-a-hyd-b300 |

示例原 target_id 带 `-independent`，请改为上表的值，或者在所有命令与标签里同步保留该后缀。Name 标签采用 `Phoenix-Codex-Local-Spot-customer-a-hyd-b300`。

保持 enabled=false、gpu-production、manual、standalone、all-approved、1/1；填写固定数字 LT version、AMI、profile ARN、SG、UserData hash、加密盘和实际 offering 的 AZ/subnet。设客户价格 cap；不开放跨区域、Local Zone 或 On-Demand fallback。资源准备与标签完整清单见 [详细 B300 手册](../hyd-b300-quickstart.md)。

## 3. 只读检查

```sh
export READ_PROFILE='REPLACE_CUSTOMER_READONLY_PROFILE'
export OP_PROFILE='REPLACE_CUSTOMER_OPERATOR_PROFILE'
export TABLE='Phoenix-Codex-Local-Spot-customer-a-State'
export LT_ARN='REPLACE_EXACT_HYD_LT_ARN'
export INSTANCE_ROLE_ARN='REPLACE_EXACT_INSTANCE_ROLE_ARN'

.venv/bin/python -m h100_spot_controller.cli validate-target privateinputs/customer-a.yaml
.venv/bin/python -m h100_spot_controller.cli discover privateinputs/customer-a.yaml --profile "$READ_PROFILE"
.venv/bin/python -m h100_spot_controller.cli preflight privateinputs/customer-a.yaml --profile "$READ_PROFILE"
.venv/bin/python -m h100_spot_controller.cli capacity-review privateinputs/customer-a.yaml --profile "$READ_PROFILE"
```

**检查点：** preflight.ready=true，B300/8 GPU/Spot、P quota、网络和启动合同通过；没有残余容量。preflight 失败退出 2，先修输入；不要解释为缺库存。

## 4. 部署客户独立控制平面

CDK CLI/已审核 bootstrap 是前提。先 diff，再批准部署（有控制平面费用）：

```sh
cdk diff Phoenix-Codex-Local-Spot-customer-a-Controller --app '.venv/bin/python app.py' \
  --profile "$OP_PROFILE" -c customer_id=customer-a -c target_id=customer-a-hyd-b300 -c region=ap-south-2
cdk deploy Phoenix-Codex-Local-Spot-customer-a-Controller --app '.venv/bin/python app.py' \
  --profile "$OP_PROFILE" -c customer_id=customer-a -c target_id=customer-a-hyd-b300 -c region=ap-south-2 \
  --parameters TargetId=customer-a-hyd-b300 \
  --parameters LaunchTemplateArns="$LT_ARN" --parameters LaunchInstanceRoleArns="$INSTANCE_ROLE_ARN"
```

**检查点：** stack 成功；CUSTOMER_ID/TARGET_ID 和 YAML 匹配；专用状态表存在。LT 和实例角色不是这个 stack 创建的。第二个客户用另一 namespace/target/profile，不共享状态表。

## 5. 先写 disabled，再启用

```sh
.venv/bin/python -m h100_spot_controller.cli target-put privateinputs/customer-a.yaml \
  --table "$TABLE" --state-region ap-south-2 --profile "$OP_PROFILE" --execute
.venv/bin/python -m h100_spot_controller.cli target-review customer-a-hyd-b300 \
  --table "$TABLE" --state-region ap-south-2 --profile "$READ_PROFILE"
```

检查 enabled=false，记录 configuration_version。容量费用另行批准后，把 YAML 的 enabled 改 true，重跑 validate/preflight，并使用最新 review 版本：

```sh
export REVIEWED_VERSION='REPLACE_CONFIGURATION_VERSION'
.venv/bin/python -m h100_spot_controller.cli target-put privateinputs/customer-a.yaml \
  --table "$TABLE" --state-region ap-south-2 --profile "$OP_PROFILE" \
  --expected-version "$REVIEWED_VERSION" --execute --enable-capacity
```

**检查点：** 相同 target 的一笔 maintain Fleet；总目标 1，不是每 AZ 1。保存 FleetId；shortfall 只表示尚未满足，不新建并行 Fleet。写结果不明时保留 intent/token，按手册诊断。

## 6. 查看结果，停止

```sh
.venv/bin/python -m h100_spot_controller.cli capacity-review privateinputs/customer-a.yaml \
  --table "$TABLE" --state-region ap-south-2 --profile "$READ_PROFILE"
```

机器出现后另外核对 nvidia-smi、驱动和业务启动。控制器 healthy 不代表业务健康。用完执行 [停机与清理](stop-and-cleanup.md)，CONFIG=privateinputs/customer-a.yaml、TARGET=customer-a-hyd-b300、REGION=ap-south-2。只关 enabled 不取消 AWS Fleet 需求。
